# NavLogger — ثبت داده GPS + ICM + OBD

این مخزن دو بخش دارد:

| پوشه | چیست |
|---|---|
| `app/` + `.github/workflows/build.yml` | برنامه اندروید (APK را GitHub Actions می‌سازد) |
| `esp32/NavIMU_BLE/` | فریم‌ور ESP32 (TTGO T-Display + ICM-45686 + QMC6309) |

برنامه و فریم‌ور با هم جفت شده‌اند؛ **فریم‌ور جدید را حتماً روی ESP32 بریزید**، وگرنه برنامه ماژول ICM را نمی‌شناسد.

---

## ۱) ساختن APK در GitHub

1. همه فایل‌های این بسته را با همین ساختار پوشه‌ها در مخزن GitHub خود بگذارید (پوشه `.github` هم باید باشد).
   - اگر در آپلود از طریق وب، پوشه `.github` منتقل نشد: در GitHub بزنید **Add file → Create new file**، نام فایل را دقیقاً `.github/workflows/build.yml` بنویسید و محتوای همین فایل را بچسبانید.
2. بعد از Commit، به تب **Actions** بروید. ساخت خودکار شروع می‌شود (یا روی **Build NavLogger APK → Run workflow** بزنید).
3. بعد از حدود ۵ دقیقه، روی اجرای سبزرنگ بزنید و از بخش **Artifacts** فایل `NavLogger-apk` را دانلود کنید. داخل آن `NavLogger.apk` است.
4. **یک بار** نسخه قبلی برنامه را از گوشی حذف کنید (کلید امضای این نسخه فرق دارد). از این به بعد هر APK جدید روی قبلی نصب می‌شود.

## ۲) ریختن فریم‌ور روی ESP32

1. در Arduino IDE از Boards Manager بسته **esp32 by Espressif** را نصب کنید.
2. Board را **ESP32 Dev Module** (یا LilyGo T-Display) بگذارید و `esp32/NavIMU_BLE/NavIMU_BLE.ino` را Upload کنید. کتابخانه اضافه‌ای لازم نیست.
3. سیم‌کشی ماژول ICM: `VCC → 3V3`، `GND → GND`، `SDA → GPIO21`، `SCL → GPIO22`.
   (اگر پایه‌های دیگری بسته‌اید، `I2C_SDA` و `I2C_SCL` بالای فایل را عوض کنید.)
4. Serial Monitor با سرعت 115200 باید نشان دهد: `IMU OK, MAG OK` و هر ثانیه `rate=100 Hz`.

## ۳) استفاده از برنامه

1. اجازه‌های **Location (Precise)** و **Nearby devices** را بدهید. بلوتوث و Location گوشی روشن باشند.
2. دکمه **تنظیمات باتری** → Battery → **Unrestricted** (تا سامسونگ در صفحه‌خاموش ثبت را قطع نکند).
3. **انتخاب آداپتور OBD**: موتور روشن باشد. `IOS-Vlink` (BLE) را انتخاب کنید.
   اگر BLE پایدار نبود، `Android-Vlink` را یک بار در تنظیمات بلوتوث گوشی Pair کنید (رمز معمولاً 1234 یا 0000) و آن را با برچسب «classic» انتخاب کنید.
4. **انتخاب ماژول ICM**: دستگاه `NAV-IMU` را انتخاب کنید.
5. **شروع ثبت**. هر سه بخش مستقل وصل می‌شوند؛ اگر یکی قطع شود خودش دوباره وصل می‌شود و بقیه ثبت ادامه می‌یابد.
6. **توقف ثبت** → فایل‌ها در `Download/NavLogger/` گوشی:
   - `nav_YYYYMMDD_HHMMSS.csv` : داده‌ها
   - `nav_..._events.txt` : زمان شروع، دستگاه‌ها، اتصال/قطعی‌ها، نرخ‌ها هر ۱۰ ثانیه

اولین اتصال OBD ممکن است تا یک دقیقه طول بکشد (پروتکل خودرو را پیدا می‌کند)؛ پروتکل پیدا شده ذخیره می‌شود و دفعه‌های بعد سریع وصل می‌شود.

## ۴) ساختار فایل CSV

هر سطر **یک اندازه‌گیری از یک منبع** است با زمان دقیق خودش؛ ستون‌های منابع دیگر **خالی** می‌مانند (نه تکرار مقدار قبلی). سطرها بر اساس زمان مرتب‌اند.

| ستون | توضیح |
|---|---|
| `t_s` | ثانیه از لحظه شروع ثبت (ساعت مشترک گوشی، دقت میکروثانیه) |
| `src` | `IMU` (حدود ۱۰۰ بار در ثانیه)، `GPS` (معمولاً ۱ بار در ثانیه)، `OBD` (هر قدر خودرو جواب دهد) |
| `lat`, `lon` | عرض و طول جغرافیایی GPS |
| `yaw_rate_dps` | نرخ یاو = ژایروی محور Z ماژول ICM (درجه بر ثانیه) |
| `mag_heading_deg` | سمت مغناطیسی خام = atan2(mag_y, mag_x)، بدون کالیبراسیون و با فرض تراز بودن ماژول |
| `obd_speed_kmh` | سرعت خودرو از OBD (km/h) |
| `gps_alt_m` … `gps_utc_ms` | ارتفاع، سرعت، جهت حرکت، دقت و زمان UTC هر fix |
| `gyro_x/y_dps`, `acc_x/y/z_g`, `mag_x/y/z_G` | داده‌های خام برای پردازش آفلاین (کالیبراسیون مگنتومتر، جبران شیب و …) |
| `imu_esp_us` | زمان نمونه با ساعت خود ESP32 (برای همگام‌سازی دقیق‌تر آفلاین) |
| `obd_rtt_ms` | زمان رفت‌وبرگشت درخواست OBD |

خواندن در پایتون:

```python
import pandas as pd
d = pd.read_csv("nav_20261018_130512.csv")
imu = d[d.src == "IMU"]; gps = d[d.src == "GPS"]; obd = d[d.src == "OBD"]
```

## ۵) نرخ‌ها و بار روی گوشی

- ICM: ۱۰۰ هرتز (ESP32 با ۵۰۰ هرتز می‌خواند و هر ۵ نمونه را میانگین می‌گیرد = فیلتر ضد‌تداخل). داده‌ها در بسته‌های ۵‌تایی (۲۰ بسته در ثانیه) فرستاده می‌شوند.
- OBD: بدون مکث، درخواست بعدی بلافاصله بعد از جواب قبلی. نرخ واقعی را ECU خودرو تعیین می‌کند (در خطوط K-line معمولاً حدود ۵ تا ۱۵ هرتز).
- GPS: هر fix که تراشه بدهد (در سامسونگ معمولاً ۱ هرتز).
- حجم فایل حدود ۵۰ مگابایت در ساعت. نوشتن با بافر انجام می‌شود و هر ثانیه روی حافظه ذخیره می‌شود؛ بار CPU ناچیز است.
- صفحه هر ۱ ثانیه به‌روز می‌شود.
